# 场景编排数据传递问题排查与修复

## 问题描述

**症状**: 单接口执行正常，场景编排执行同一接口时报错"参数未传递"

**根本原因**: 场景编排的数据处理逻辑与单接口不同

---

## 一、数据流转对比

### 单接口执行流程

```
前端界面 → request.data → views.execute() → 直接发送
```

**数据来源**: 前端实时传递的完整数据

### 场景编排执行流程

```
前端保存 → Database (override_body) → get_effective_request_data() → 
resolve_in_dict() → _send_request()
```

**数据来源**: 数据库中存储的 override_body

---

## 二、关键差异点

### 1. 数据存储格式

**单接口**: 前端直接发送完整数据
```json
{
  "method": "POST",
  "url": "/api/test",
  "body": {
    "type": "form-data",
    "data": [
      {"key": "kb_id", "value": "123", "type": "string", "enabled": true}
    ]
  }
}
```

**场景编排**: 存储到 override_body (JSONField)
```python
# models.py - ScenarioStep
override_body = models.JSONField(default=dict, blank=True)

# get_effective_request_data()
if self.override_body:
    request_data['body'] = self.override_body
```

### 2. 数据合并逻辑

**单接口**: 无合并，直接使用
**场景编排**: 合并原始接口数据 + 覆盖配置

```python
# 关键代码：get_effective_request_data()
request_data = {
    'method': self.api_request.method,
    'url': self.api_request.url,
    'body': self.api_request.body,  # ← 原始接口的 body
}

if self.override_body:
    request_data['body'] = self.override_body  # ← 替换为覆盖的 body
```

**问题**: 如果 override_body 为空或格式不正确，会导致数据丢失！

---

## 三、常见问题场景

### 问题 1: override_body 未正确保存

**症状**: 场景步骤保存了，但 override_body 为空或格式错误

**原因**:
- 前端保存时未包含完整的 body 数据
- override_body 默认值为空 dict
- 数据格式转换错误

**检查方法**:
```sql
-- 检查数据库中的 override_body
SELECT id, name, override_body FROM api_scenario_steps WHERE id = <step_id>;
```

**预期结果**:
```json
{
  "type": "form-data",
  "data": [{"key": "kb_id", "value": "123", "enabled": true}]
}
```

**实际可能结果**:
```json
{}  // 空 dict
或
null  // null 值
或
{"type": "form-data", "data": []}  // 空数组
```

### 问题 2: enabled 字段缺失或为 false

**症状**: 数据存在，但字段被过滤掉

**原因**: executor 处理时检查 enabled 字段

```python
# executor.py 中的处理逻辑（可能存在）
if item.get('enabled', True):  # ← 如果 enabled=false，字段会被跳过
    multipart_data[key] = value
```

**检查方法**:
```json
// 检查每个字段的 enabled 状态
{
  "key": "kb_id",
  "value": "123",
  "enabled": false  // ← 问题：字段被禁用
}
```

### 问题 3: form-data 处理逻辑不同

**症状**: JSON 类型正常，form-data 类型报错

**原因**: executor 对 form-data 的处理逻辑可能与单接口不同

**单接口处理** (views.py):
```python
# 单接口的 form-data 处理
if body_type == 'form-data':
    # 完整的 form-data 处理逻辑
    for item in form_data_items:
        if item.get('key'):
            form_dict[item['key']] = item.get('value', '')
```

**场景编排处理** (executor.py):
```python
# 场景编排的 form-data 处理（可能简化或有bug）
if body_type == 'form-data':
    # 需要检查这里的逻辑是否完整
```

### 方案 3: 确保 executor 正确处理 form-data

**在 executor.py 的 _send_request 方法中**:

```python
def _send_request(self, request_data: Dict) -> Dict:
    """发送 HTTP 请求"""
    # ... 前面的代码
    
    body = request_data.get('body', {})
    
    # ✨ 添加详细日志
    print(f"DEBUG - _send_request body: {body}")
    
    # 处理 body 格式
    if isinstance(body, dict) and 'type' in body:
        body_type = body.get('type')
        body_data = body.get('data')
        
        print(f"DEBUG - body_type: {body_type}")
        print(f"DEBUG - body_data: {body_data}")
        
        if body_type == 'form-data':
            # ✨ 关键：确保完整处理 form-data
            multipart_data = {}
            
            if isinstance(body_data, list):
                print(f"DEBUG - Processing {len(body_data)} form-data items")
                
                for item in body_data:
                    key = item.get('key')
                    value = item.get('value')
                    enabled = item.get('enabled', True)  # ✨ 默认 true
                    
                    print(f"DEBUG - item: key={key}, value={value}, enabled={enabled}")
                    
                    # ✨ 修复：只有 enabled=true 才添加
                    if key and enabled:
                        multipart_data[key] = str(value)
                        print(f"✅ DEBUG - Added: {key}={value}")
                    else:
                        print(f"❌ DEBUG - Skipped: {key} (enabled={enabled})")
                
                print(f"DEBUG - Final multipart_data: {multipart_data}")
                
                # 检查 kb_id 是否存在
                if 'kb_id' in multipart_data:
                    print(f"✅ DEBUG - kb_id will be sent: {multipart_data['kb_id']}")
                else:
                    print(f"❌ DEBUG - kb_id NOT in multipart_data!")
                
                # 发送请求
                request_kwargs['data'] = multipart_data
```

## 六、常见修复方法

### 修复 1: 前端保存时确保数据完整

**问题**: override_body 保存不完整

**修复**: 在 AutomationSuiteDetail.vue 中确保保存完整数据

```javascript
// 构建完整的 override_body
const buildOverrideBody = () => {
  if (editingRequestData.value.bodyType === 'form-data') {
    return {
      type: 'form-data',
      data: editingRequestData.value.formData.filter(item => 
        item.key.trim() && item.enabled !== false  // ← 过滤空 key 和禁用字段
      ).map(item => ({
        key: item.key.trim(),
        value: item.value,
        type: item.type || 'string',
        enabled: item.enabled !== false,  // ← 确保 enabled 为 true
        description: item.description || ''
      }))
    }
  }
  // ... 其他类型处理
}
```

### 修复 2: 后端确保默认值正确

**问题**: enabled 字段缺失导致被跳过

**修复**: 在 executor.py 中确保默认处理

```python
# 修复：确保默认值为 true
enabled = item.get('enabled', True)  # ← 默认 true，而不是 false

# 或者更保守的处理
enabled = item.get('enabled')
if enabled is None:  # ← 只有明确为 None 时才默认 true
    enabled = True
```

### 修复 3: 处理空 override_body

**问题**: override_body 为空导致使用原始接口数据

**修复**: 在 get_effective_request_data 中检查

```python
def get_effective_request_data(self):
    request_data = {
        'body': self.api_request.body,
    }
    
    # ✨ 修复：只有 override_body 不为空才替换
    if self.override_body and isinstance(self.override_body, dict) and self.override_body.get('type'):
        request_data['body'] = self.override_body
    
    return request_data
```
