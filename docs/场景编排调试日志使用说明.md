## 关键修复说明

### 问题根源

**原代码问题**:
```python
# ❌ 错误：enabled 字段可能为 None，导致字段被跳过
enabled = item.get('enabled')  # 返回 None 或 False
if enabled:  # None 被当作 False，字段被过滤掉
    multipart_data[key] = value
```

**修复后代码**:
```python
# ✅ 正确：enabled 默认为 True，确保字段不被意外跳过
enabled = item.get('enabled', True)  # 默认 True
if enabled:  # None 时使用默认值 True，字段正常发送
    multipart_data[key] = value
```

### 为什么单接口正常，场景编排报错

**单接口执行**:
- 前端直接发送完整数据
- 没有 enabled 字段检查逻辑
- 所有字段都会被发送

**场景编排执行**:
- 数据存储在 `override_body` (JSONField)
- executor 有 enabled 字段检查逻辑
- **如果 enabled 字段缺失或为 None，字段会被过滤掉** ← 这是问题根源！

## 调试日志关键检查点

### 检查点 1: override_body 数据

```
[DEBUG] override_body: {
  "type": "form-data",
  "data": [
    {"key": "kb_id", "value": "123", "enabled": true}  ← 检查是否有 enabled 字段
  ]
}
```

**可能的问题**:
- ❌ override_body 为空 `{}`
- ❌ data 数组为空 `[]`
- ❌ 缺少 enabled 字段 `{"key": "kb_id", "value": "123"}` ← 这会导致字段被过滤

### 检查点 2: enabled 状态

```
[DEBUG] 字段 [0]:
[DEBUG]   enabled: True  ← 必须为 True
```

**可能的问题**:
- ❌ enabled: False ← 字段被禁用
- ❌ enabled: None ← 字段被跳过（修复后会默认 True）

### 检查点 3: multipart_data 最终结果

```
[DEBUG] multipart_data: {'kb_id': '123456'}
✅✅✅ [DEBUG] kb_id 将被发送: 123456
```

**可能的问题**:
- ❌ multipart_data 不包含 kb_id
- ❌ multipart_data 为空
