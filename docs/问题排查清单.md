## 一、快速诊断步骤

### 步骤 1：确认问题步骤 ID

找到你的场景步骤 ID，可以通过：
- 前端界面查看步骤详情
- 或查看数据库：`SELECT id FROM api_scenario_steps WHERE name LIKE '%步骤名称%';`

### 步骤 2：运行诊断脚本

```bash
cd grt_testhub
python diagnostic_script.py <你的步骤ID>

# 示例
python diagnostic_script.py 123
```

**脚本会告诉你**:
- ✅ override_body 是否为空
- ✅ kb_id 是否存在于 override_body
- ✅ enabled 字段的值
- ✅ effective_request_data 中是否包含 kb_id

### 步骤 3：查看控制台日志

执行场景后，查看控制台的 DEBUG 输出：
- ✅✅✅ = 成功
- ❌❌❌ = 失败

## 二、常见问题场景

### 问题 A: override_body 为空

**症状**: 
```
❌❌❌ override_body 为空或 None!
```

**原因**: 前端保存时未包含完整的 body 数据

**修复**: 检查前端保存逻辑

**临时解决**: 重新编辑步骤并保存

---

### 问题 B: kb_id 不存在于 override_body

**症状**:
```
❌❌❌ kb_id 不存在于 override_body 中!
```

**原因**: 
1. 前端保存时 kb_id 字段被过滤
2. 用户未添加 kb_id 字段
3. 数据格式转换错误

**修复**: 
1. 重新编辑步骤
2. 确保 KeyValueEditor 包含 kb_id 字段
3. 保存后再次执行

---

### 问题 C: enabled 字段为 false

**症状**:
```
enabled: False ← 字段被禁用
```

**原因**: 用户手动禁用了字段，或前端默认值错误

**修复**: 
1. 编辑步骤，勾选 enabled
2. 或等待后端修复生效（已修复默认值为 True）

---

### 问题 D: override_body 格式错误

**症状**:
```
override_body: {"data": "wrong_format"}
```

**原因**: 数据格式不符合预期

**预期格式**:
```json
{
  "type": "form-data",
  "data": [
    {"key": "kb_id", "value": "123", "enabled": true}
  ]
}
```

**修复**: 手动修正数据库数据，或重新保存

## 四、手动修复方法

### 修复 1: 直接修改数据库

如果 override_body 数据有问题，可以直接修改：

```sql
-- 查看当前数据
SELECT id, override_body FROM api_scenario_steps WHERE id = <step_id>;

-- 修正数据（示例）
UPDATE api_scenario_steps 
SET override_body = '{"type": "form-data", "data": [{"key": "kb_id", "value": "123", "type": "string", "enabled": true}]}'
WHERE id = <step_id>;
```

### 修复 2: 通过 API 更新

```bash
curl -X PATCH http://localhost:8000/api-testing/scenario-steps/<id>/ \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "override_body": {
      "type": "form-data",
      "data": [
        {"key": "kb_id", "value": "123", "type": "string", "enabled": true}
      ]
    }
  }'
```
